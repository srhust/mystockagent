# mystockagent — A股 V2 双引擎周期反转系统完整任务书 (Ashare Dual-Cycle V2)

## 0. 项目背景与目标

仓库 `srhust/mystockagent`, 本地 `E:\mystockagent`。当前 A 股系统以 `cycle_system/swing_m1.py` 为核心（行业阶段过滤+个股评分+日/月出入场）。与核心目标偏差：我们要捕捉**周期底部到主要上涨阶段**，不是行业轮动或短期均线趋势。

开发独立 **Ashare Dual-Cycle V2**，与美股周期系统理念一致：
1. Fast-V：抓急跌后的快速反转。
2. Long-Cycle：抓中长期产业周期反转。
3. 双引擎独立识别、独立跟踪状态。
4. 统一资金竞争，按机会质量动态集中配置。
5. 不限行业数量，不要求固定分散。
6. 以反转失败和趋势真正破坏退出，不按固定持仓天数卖出。
7. 历史判断只用当时可得信息。
8. 新模型不得通过修改旧结果宣称更好历史表现。

## 2. Long-Cycle（P0, 主引擎）

### 2.1 目标
识别产业从衰退→出清→底部形成→复苏→扩张。研究窗口 12/24/36 个月; 持仓数月至一年以上; **持仓天数不能作为固定卖出条件**。

### 2.2 三层周期信息
**A 产业基本面（可插拔适配器, 按行业选真实经济指标）**: 猪周期(猪价/能繁母猪/成本/利润)、铜(供需/库存/产能/TC-RC/价格)、黄金(实际利率/金价/产量/成本)、煤炭(煤价/库存/产量/需求/盈利与资本开支)、工程机械(销量/开工/更新/库存/盈利)、半导体(库存/订单/价格/资本开支/盈利)、银行(净息差/信贷/资产质量)、证券(成交/融资/投行/盈利)、保险(利率/权益/投资收益)。常山北明等成长股用独立成长景气适配器, 不强行套商品周期。
**B 行业市场表现(候选特征)**: 120/250/500日价格区间位置; 60/120/250日趋势; 6/12/24个月动量; 相对上证/沪深300强度; 中长期回撤与波动; 底部形成/上涨加速/趋势受损结构。
**C 个股确认**: 盈利与行业周期一致性; 个股相对行业强弱; 是否率先筑底; 流动性; 公司自身重大风险。

### 2.3 状态机
`DOWNTREND / BOTTOM_WATCH / BOTTOM_FORMING / EARLY_RECOVERY / EXPANSION / TREND_IMPAIRED / INVALIDATED / UNKNOWN`。允许正常迁移与失败回退。**不得用未来最低点标注历史底部。**

### 2.4 入场
同一引擎三类入口: 早期反转 / 突破确认 / 趋势延续（回撤后继续参与）。不得变成三个竞争的短线策略。

### 2.5 退出
禁止固定天数退出。MA20 破位仅预警不等于趋势失效。综合: 底部假设被否定/中期长期趋势实质破坏/个股持续显著弱于行业/公司经营风险/风险预算触发/更优机会满足换仓条件。区分 `WARNING / REDUCE / EXIT`。

## 3. Fast-V（P0, 完全独立）

### 3.1 目标
恐慌/流动性冲击/快速下跌后的强反弹。数日至数周, 不强制按日平仓。

### 3.2 检测(候选特征)
5/10/20日跌幅与速度; 高点回撤; 下跌加速度; 波动率异常; 成交量与恐慌释放; 低点不再下移; 企稳反弹确认; 行业与市场环境; 事件风险。核心判断: **快速下跌是否正转变为可参与的修复机会?** 不得事后用最低价触发。

### 3.3 状态机
`NO_SETUP / SHOCK_DETECTED / BOTTOM_SEARCH / REVERSAL_CANDIDATE / ENTRY_CONFIRMED / REBOUND_ACTIVE / REVERSAL_FAILED / EXPIRED`。可在长期趋势仍弱时独立发现机会; 但不绕过停牌/重大风险/执行底线。

### 3.4 与 Long-Cycle 的区别
互不为前置条件。同股双引擎必须记录两套理由, 由冲突处理器统一决定目标持仓, 不得重复占用资金。

### 3.5 退出
以反弹失败/修复衰竭/趋势重新转弱/风险失效退出; 不沿用长期退出规则。

## 4. 行业优先与机会评分（P0）

保留"先行业、后个股"原则, 允许 Fast-V 个股级特殊冲击。每个机会输出: 行业及分类版本/股票/来源引擎/周期阶段/关键证据/信号首现日期/当时可用特征/入场条件/失效条件/预期研究持有周期/风险估计与数据可信度/机会评分/为何交易或不交易。评分必须可解释; **无校准前不得称"预期收益率"或"胜率"**; 不得只按20日动量排名。

## 5. 统一资金竞争与贪心分配（P0）

### 5.1 原则
资金不预分引擎(禁止固定 40/60), 不固定持仓数量。按当日合格机会统一竞争。

### 5.2 集中配置
无好机会→现金; 单一优势行业→允许高度集中; 两个领先行业→集中两行业; 多个低相关→适度分散; 新机会显著更优→评估后换仓。**不复制 30% 单股上限等旧参数为默认**; 允许研究单行业 60%+, 实际比例由风险预算与可成交约束决定。

### 5.3 Greedy Allocator
接收双引擎全部合格机会→统一评分与风险尺度→合并同股与高重叠→评估持仓/新机会/现金/相关性→按风险调整后边际机会价值排序→贪心分配→每笔重算剩余风险预算→无可信正边际即停→输出目标持仓与未分配现金。先用保守可解释排序式贪心; 校准后再考虑优化器。

### 5.4 风险约束
行业相关性与共同因子; 流动性与成交量; 波动与尾部; 压力情景; T+1; 涨跌停不可成交; 持仓重叠; 费用与现金预留; 换仓成本。不用融资杠杆; 不允许评分高就无约束满仓。

### 5.5 换仓纪律
最小优势差距/成本比较/原逻辑是否成立/风险预算变化/抑制不必要换手。阈值事先固定用于工程测试, 不得按旧样本收益寻优。

## 6. 双引擎持仓协调（P0）

Portfolio Coordinator: 双引擎独立虚拟持仓与归因, 真实组合共享总资金账本。每笔持仓带来源引擎与初始判断; 同股不重复承诺资金; 卖出指明虚拟头寸; 统一生成净目标仓位与真实买卖计划; 风险强制退出可覆盖引擎决策; 一般预警不自动清除另一引擎持仓; **卖出优先于依赖卖出资金的新增买入**; 不重复登记 SELL/重复扣费。优先复用 `ashare_executor.py`, 必须改则用适配层, 不破坏冻结基线。

## 7. 历史数据与 PIT 可信度（P0）

### 7.1 股票池
复用 Baostock 上市/退市信息与已有审计。区分: 当时已上市/上市存续/有行情/确认停牌/历史ST/流动性/数据足够。**禁止以当前249池宣称已消除幸存者偏差。**

### 7.2 行业分类
统一 Industry Membership Provider, 区分: `SW_PIT_VERIFIED / SW_PARTIAL / CSRC_HISTORICAL_DATE / CURRENT_SNAPSHOT_ONLY / UNKNOWN`。证监会分类不得冒充申万二级; 缺历史申万成员可出受限研究诊断但不得当真实历史回测; 2014/2021 版本显式区分; **不得拼接语义不同的行业指数**。

### 7.3 基本面与周期数据
每条记录: 所属期间/原始值/来源/首次公开时间/生效时间/系统获取时间/修订版本/完整性与可信度。策略只能在数据实际可知后使用(如季度利润不等于季度末当天可知)。缺可靠发布时间默认 `UNKNOWN`, 不回填。

### 7.4 数据不足行为
**Strict**: 关键时点信息缺失→拒绝正式交易信号。**Research**: 允许价格代理但输出 `PROXY_ONLY / DATA_LIMITED / UNKNOWN`, 不归类为已验证策略。禁止静默用今天快照填补历史映射。

## 8. 单日市场诊断（P1）

按最近已确认交易日输出: **大盘**(主要指数中长期趋势/风险环境/宽度与波动/系统性快速反转机会); **行业**(生猪养殖/铜/黄金/煤炭/银行/证券/保险及其他已配置周期——长期阶段+6-12月状态+短期修复); **重点个股**(牧原股份/江西铜业/招金黄金/常山北明——Long-Cycle 阶段/Fast-V 阶段/证据/核心风险/关键与失效条件/数据是否足够/是否合格候选)。数据不足显示缺失, 不猜测。常山北明走成长适配器, 不进传统商品周期排名。

## 9. 验证与回测（P0）

### 9.1 工程测试
无未来信息泄漏; 产业指标晚于信号日不可见; 双状态机独立; Fast-V 可独立发候选; Long-Cycle 不按固定天数退出; 同股双引擎不重复占资金; 现金与股票守恒; 订单顺序无关性; T+1 符合; 现金不透支; 停牌/涨跌停/ST 不明安全行为; 无数据 Fail-Closed; 风险限制触发; 单行业高集中与空仓边界; 旧 B0/B1/F2 与测试不退化。

### 9.2 合成场景
A 长期下行后产业先改善价格后反转; B 暴跌后 V 形修复但长期弱; C 中长期上涨中正常回撤不因 MA20 清仓; D 反转假设否定必须退出; E 两强机会集中两行业; F 单强机会高集中但风险受限; G 无机会持现金; H 行业缺失严格模式拒交易。

### 9.3 历史研究纪律
2020–2026 已反复研究, 不再是 OOS。允许: 工程回放/执行一致性/状态机调试/历史解释性研究/与冻结基线描述性比较。**禁止参数遍历挑最优再宣称有效。**

### 9.4 正式评价
数据时点解决+规则冻结后才做: 单引擎/联合/基线比较/贪心 vs 简单配置/市场阶段分层/成本与不可成交敏感性/回撤/Calmar/Sharpe/换手/现金占比/集中度/覆盖/底部发现延迟。真正预测有效性需独立未见数据或冻结后前向影子运行。

## 10. 运行模式与交付文件

A **Diagnostic**(只读诊断, 不真实成交); B **Synthetic/Replay**(人工+冻结数据测试, 不包装为样本外绩效); C **Paper/Shadow**(收盘形成计划, 次日按真实约束模拟, 记录计划/拒单/成交/持仓/现金/NAV/数据快照)。三模式共享同一核心信号与资金逻辑。输出: `cycle_state_daily.json / fast_v_candidates.json / long_cycle_candidates.json / opportunity_ranking.json / capital_allocation.json / trade_plans.json / risk_report.json / daily_cycle_report.md / data_quality_report.json / experiment_manifest.json`。每份记录代码版本/配置/数据哈希/信息时点。

## 11. 实施顺序

A 冻结与设计(确认旧基线未改, 建目录/数据契约/设计文档) → B 数据基础(统一访问/PIT/历史股票池/行业状态, 缺数据明确报告) → C 双引擎(状态机/候选/退出) → D 机会比较与资金(评分/贪心/风险/换仓/协调) → E 执行整合(T+1/费用/共享账本, 不改旧行为) → F 诊断与影子(单日报告/合成/回放/影子入口) → G 统一验收(全部测试/数据时点/资金守恒/执行一致性/完整报告)。可分阶段 commit, 目标与验收规则开始时一次定死。

## 13. 最终要求

不是参数优化, 是架构升级。不以提高 2020–2026 回测收益为目标。旧系统保留为可复现对照; 新系统首先证明: **能够在当时信息下识别快速反转或长期周期底部, 区分正常回撤与趋势失效, 并把资金集中分配给真正有优势的机会。** 交付完整代码/测试/架构文档/可执行命令/数据限制报告/验收总结。**不得将编译通过、测试通过、远端同步或预测有效混为同一完成状态。**
